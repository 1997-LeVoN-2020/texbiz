Страницы услуг, решений и статей — записи в базе, а не отдельные шаблоны. Новый шаблон нужен только для страницы принципиально другого устройства.

## Сначала согласовать

Показать владельцу заголовок, слаг и состав разделов, дождаться ответа, и только потом писать. На этом проекте несогласованные тексты уже переписывались по нескольку раз. Факты не выдумывать: цифры, цены, сроки и перечни оборудования берутся только от владельца, иначе в тексте остаётся пометка `[уточнить: …]`. Сам текст пишет агент `content-writer`.

## Услуга

Файл `web/fixtures/services.json`, модель `web.service`.

```json
{
  "model": "web.service",
  "pk": 9,
  "fields": {
    "title": "Название услуги",
    "slug": "nazvanie-uslugi",
    "icon": "OPS",
    "summary": "Текст карточки в списке услуг, до 300 знаков.",
    "lead": "Лид-абзац страницы. Пусто — страницы нет, только карточка.",
    "body": "<h2>Что входит</h2>\n<div class=\"features\">…</div>",
    "meta_title": "Название услуги | ТЕХБИЗ",
    "meta_description": "Описание для выдачи, 70–180 знаков.",
    "order": 9,
    "is_published": true
  }
}
```

- `pk` и `order` — следующие свободные, нумерацию существующих не сдвигать.
- `icon` — код из `web/icons.py`, новые значки не изобретать.
- **Пустой `body` означает карточку без своей страницы.** Так сделаны «Поддержка и сопровождение», «Интеграция каналов продаж», «Миграция и запуск без простоя», «Обучение персонала»: они показываются в списке, но ссылки на страницу не имеют.
- Адрес получается `/<slug>/` — в корне сайта, как на прежней версии.

## Решение по формату объекта

Файл `web/fixtures/solutions.json`, модель `web.solution`. Поля `title`, `slug`, `body`, `order`, `is_published`. Отдельной страницы нет: это блок на `/resheniya/`, слаг работает якорем.

## Статья блога

Файл `blog/fixtures/articles.json`, модель `blog.article`. Поля `title`, `slug`, `excerpt`, `body`, `published_at` (формат `2026-09-06T09:00:00+03:00`), `meta_title`, `meta_description`, `is_published`.

Дата в будущем откладывает публикацию: статья появится сама. `is_published: false` — черновик.

## Разметка в поле body

Готовый HTML без обёрток страницы. Разрешено: `<h2>`, `<h3>`, `<p>`, `<ul>`, `<ol>`, `<li>`, `<strong>`, `<a>`. Для вопросов — `<details class="faq-item"><summary>…</summary><p>…</p></details>`. Для блока «что входит» на странице услуги — `<div class="features">` с карточками `<div class="feature"><h3>…</h3><p>…</p></div>`.

Классы брать из существующих записей: под новые нет стилей. Тегов шаблонизатора в фикстурах быть не должно, ссылки — обычные `href="/uslugi/"`.

## Применить и проверить

```
.venv/Scripts/python manage.py loaddata services solutions articles
.venv/Scripts/python scripts/check_site.py
```

`loaddata` перезаписывает записи по `pk`, поэтому команду можно повторять сколько угодно. Затем открыть страницу локально через скилл `preview-site`.

Меню в `templates/includes/header.html` жёсткое, из пяти пунктов: новая услуга или статья туда не попадает и не должна.

## Чего не делать

Не менять слаг у уже опубликованной страницы: адрес проиндексирован. Не заводить разделы «Оборудование», «Программные продукты» и «О компании» — по решению от 06.09.2026 они отложены до появления содержимого.
