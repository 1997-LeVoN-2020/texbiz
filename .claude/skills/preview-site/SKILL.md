## Порядок

1. Если виртуального окружения нет, создать и поставить зависимости:

```
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
```

2. Если нет файла `.env`, скопировать `.env.example` и включить режим отладки: `DJANGO_DEBUG=1`, `DJANGO_SECRET_KEY=dev-local-key`, `SITE_URL=http://127.0.0.1:8010`. Без ключа в боевом режиме настройки намеренно падают.

3. Если нет базы (`data/db.sqlite3`) или она пустая:

```
.venv/Scripts/python manage.py migrate
.venv/Scripts/python manage.py loaddata services solutions articles
```

Должно быть 8 услуг, 4 решения, 12 статей.

4. Поднять сервер через `mcp__Claude_Browser__preview_start` с конфигурацией **`django-dev`** из `.claude/launch.json`.

## Про порт

Порт **8010**, не 8000: 8000 занят сервером другого чата. В `launch.json` стоит `autoPort: false`, потому что порт зашит в аргументы `runserver`. Если порт занят уже этим проектом, `preview_start` переиспользует запущенный сервер — это нормально.

## Проверка, что всё поднялось

Открыть `http://127.0.0.1:8010/` и убедиться, что страница со стилями. Страница без оформления означает, что не отдаётся `static/css/main.css`: в режиме отладки статику раздаёт сам Django, значит `DJANGO_DEBUG` не включён.

Ошибки сервера смотреть через `mcp__Claude_Browser__preview_logs`, ошибки страницы — через `read_console_messages`.

## Чего не делать

Не запускать `runserver` через Bash: процесс останется висеть и займёт порт. Только `preview_start`, останавливать — `preview_stop`.

Не открывать шаблоны как файлы через `file://`: без сервера не работают ни адреса, ни подстановка данных из базы.
