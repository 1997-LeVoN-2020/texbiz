## Команда

```
.venv/Scripts/python scripts/check_site.py
```

Сервер поднимать не нужно: скрипт работает через тестовый клиент Django. Код возврата 1, если есть ошибки; предупреждения на код возврата не влияют.

## Что проверяется

- Все страницы отдают 200: главная, услуги и четыре страницы услуг, решения, бронирование, контакты, политика, «Спасибо», блог и двенадцать статей.
- Несуществующий адрес отдаёт 404.
- Внутренние ссылки из HTML открываются.
- Файлы статики, на которые ссылается разметка, существуют на диске.
- `title` и `description` есть, уникальны по всему сайту и укладываются в длину для выдачи. У страниц с `noindex` длина не проверяется.
- `canonical` совпадает с `SITE_URL` плюс путь страницы.
- Все блоки JSON-LD разбираются как JSON.
- В выводе не осталось фрагментов шаблона (`{{` или `{%`): признак того, что в фикстуру попал шаблонный код.
- `sitemap.xml` содержит все публичные страницы и не содержит служебных; `robots.txt` ссылается на карту сайта.

## Разбор находок

**Ошибки** правятся до публикации. Частые причины:

- ссылка ведёт на адрес, которого нет — опечатка в фикстуре или переименованный слаг;
- файл статики не найден — забыли добавить файл или опечатались в `{% static %}`; в боевом режиме это ещё и валит `collectstatic`;
- `title` повторяется — две страницы конкурируют в выдаче за один запрос;
- `canonical` не совпал — в `.env` стоит не тот `SITE_URL`.

**Предупреждения** по длине метатегов — повод переписать текст, но публикацию не блокируют.

## Чего скрипт не проверяет

Смысл текстов, вёрстку и контраст. Для вёрстки на разных ширинах есть агент `layout-qa`, для смысла метатегов и разметки — `seo-auditor`, для соответствия брендбуку — `brandbook-checker`.
